# 보스 1 구현 스펙 (초안)

기준 기획서: [보스 1 기획서](https://docs.google.com/document/d/1Tu8DF-FWIpEfTEjQ8aPzSX1BByPHi8ggqBuXXy6t9Cg) (2026-11-12 원본 기준)
상태: **합의됨 (2026-11-12)**. 기획서와 다른 부분은 8장 "결정 사항"이 우선한다.

## 1. 범위

- 포함: 보스 본체 AI(패턴 7종 + 부스트 스텝), 2페이즈, 미사일 3종, 경고 표시, **플레이어 피격 로그**(체력 없이 `Debug.Log`만), 보스 전용 테스트 씬
- 제외: 정식 아트·애니메이션(색이 바뀌는 사각형/스프라이트로 예고를 대신함), 보스 사운드, 사망 이후 연출(보상·해금), 보스 이름

## 2. 기존 코드와의 연결점

| 필요한 것 | 현재 코드 | 처리 |
|---|---|---|
| 보스가 피해를 받음 | `Damageable`, `TrainingDummy`의 체력·`HealthBarUI` 패턴 | `Boss1`이 `Damageable`을 상속. 체력바는 `HealthBarUI`를 그대로 씀 |
| 플레이어 평타·히트스톱·리듬 획득 | `PlayerAttack.HitConfirmed` → 연출·리듬 | 수정 없음 (보스가 `TryTakeDamage`에서 true만 돌려주면 됨) |
| 플레이어가 피해를 받음 | **없음** | `PlayerHealth`를 새로 만든다 (지금은 로그만) |
| 보스 피격 시 리듬 감소 | `PlayerRhythmGauge.NotifyBossDamageTaken()` (호출하는 곳 없음) | 이번엔 연결하지 않음. 피격 처리를 만들 때 `PlayerHealth`에서 한 줄로 호출 |
| 슬라이드 높이 | `PlayerMovement.slideColliderHeight = 0.6` | 펀치 판정 하단 계산에 씀 |
| 본체끼리 밀지 않음 | `ZombieMovement`의 `Physics2D.IgnoreCollision` | 같은 방식 |

## 3. 구성 요소 (새 파일 6개, `Assets/Scripts/Boss/`)

| 파일 | 역할 |
|---|---|
| `PlayerHealth.cs` (Player/) | `Damageable` 상속. 피격 시 `Debug.Log`(공격 이름·피해 비율)만 남기고 true 반환. 체력·무적·사망 없음 |
| `Boss1.cs` | `Damageable` + 두뇌. 체력·페이즈 전환 예약·행동 우선순위·패턴 코루틴 7종·부스트 스텝·사망 정리. 패턴은 기획서 그대로 순서가 정해진 시퀀스라 코루틴 하나씩으로 충분하다 |
| `Boss1Missiles.cs` | 본체와 따로 도는 타이머: 조준 미사일(6초), 난사(20초), 최소 0.35초 간격 규칙, "화면에 조준 1발" 관리 |
| `EnemyHitbox.cs` | 켜져 있는 동안 영역 안의 `PlayerHealth`에 **활성화 1회당 1번** 피해. 근접·착지·돌진·폭발이 모두 이것을 씀 |
| `Shockwave.cs` | 착지 충격파. `EnemyHitbox`를 들고 좌우로 이동, 4H 뒤 소멸 |
| `BossMissile.cs` | 경고 원/선 표시 → 비행 → 착탄 시 폭발 `EnemyHitbox`(0.4H, 0.2초). 후방·조준·난사가 같은 프리팹을 씀. 조준 미사일만 **비행 중 몸체 판정**을 켠다 |

- 프리팹: `Boss1`, `BossMissile`, `Shockwave`. 씬: `Assets/Scenes/Boss01.unity`(평지 아레나 + 양쪽 벽 + 플레이어). Unity MCP로 만든다.
- 아레나 경계는 보스 인스펙터의 `arenaMinX / arenaMaxX` 두 값으로 둔다(벽 감지 레이캐스트 없이).

## 4. 거리 단위 H (실측)

플레이어 몸 콜라이더 높이 1.31 → **1H = 1.31 유닛**. `Boss1`에 `unitH = 1.31` 필드 하나를 두고 모든 거리 수치는 H 배수로 입력받는다.

현재 플레이어 성능으로 계산한 값 (jumpSpeed 10, gravityScale 3):

| 항목 | 값 | 기획서 요구와 비교 |
|---|---|---|
| 점프 최고 높이 | 1.70 유닛 = **1.30H** | 1타 판정 높이 **0.9H**(결정 1) → 발이 0.9H 위에 있는 시간 **약 0.38초**, 판정 0.15초를 여유 있게 넘음 |
| 점프 체공 | 0.68초 | 1타 후 2타 판정까지 1.1초 → 착지 조건 충족 |
| 충격파 0.5H 위 체공 | 0.53초 | 충격파 두께가 얇으면 충분 |
| 슬라이드 높이 | 0.6 유닛 = 0.46H | 펀치 판정 하단 ≥ **0.56H** (0.73 유닛) |
| 이동 속도 | 8 유닛/초 = 6.1H/초 | 내려찍기 범위 2H를 0.33초에 빠져나감 |

## 5. 조정 가능한 수치 (전부 인스펙터)

기획서 "패턴 수치 초안" 표와 피해 비율을 그대로 `[SerializeField]`로 옮긴다. 패턴마다 `[Header]` 하나씩:

- 3타: 예고(0.65/0.75/0.85), 회전 0.25, 판정(0.15/0.15/0.20), 중간 틈 0.35, 후딜 0.55, 범위(1.5H×0.9H / 2H / 2H), 재사용 1초
- 돌진: 선택 거리 2.5H, 예고 0.85, 거리 4H, 시간 0.55, 제동 0.60, 재사용 5초
- 도약: 선택 거리 2.5~6H, 예고 0.8, 체공 0.7(착지 지점 위까지 상승 이동 0.35 → X 고정·가속 수직 낙하 0.35, 정점 대기 없음), 높이 2.5H(출발점과 착지점 중 높은 쪽 기준), 수직 하강 시작~착지 직후 0.15초 동안 몸통 BoxCollider2D와 같은 크기·위치의 트리거 판정, 바닥 반경 1.0H는 경고 표시, 충격파 높이 0.5H·속도 8H/초·거리 4H, 후딜 0.55, 재사용 6초. 몸통·충격파를 합쳐 도약 1회당 한 번만 피해.
- 백스텝: 조건 1.2H·1.5초, 예고 0.35, 거리 3H/0.3초, 연계 대기 0.3, 재사용 6초
- 후방 미사일: 조건 2H·0.8초, 예고 0.8, 착탄점 1.0H/2.5H, 비행 0.6, 후딜 0.50, 재사용 7초
- 조준 미사일: 주기 6초, 추적 1.6초, 고정 0.4초, 미사일 속도, 비행 판정 크기
- 난사: 첫 사용 20초, 주기 20초, 준비 1.0, 30발, 간격 0.2초, 산포 ±0.25H, 착탄 예고 0.8, 후딜 0.60
- 공통: 패턴 사이 대기 0.4, 스텝(준비 0.2 / 1.2H·0.2초 / 정지 0.3), 폭발 반경 0.4H·0.2초, 미사일–본체 최소 간격 0.35초
- 피해 비율(플레이어 최대 체력 대비): 6/6/10/10/10/6/미사일 6%
- 2페이즈: 예고 배율 0.8, 패턴 사이 대기 0.25 (그 외 스텝 정지·재사용 대기는 1페이즈 값 유지)
- 보스 최대 HP (90~120초 목표로 플레이테스트 후 조정)

## 6. 동작 규칙 요약 (구현 기준)

- **행동 선택**(본체가 대기 중일 때만): 사망 → 페이즈 전환 예약 → 난사 예약 → 후방 미사일 → 백스텝 → 원거리(돌진/도약 중 재사용 끝난 것 무작위) → 3타 → 없으면 부스트 스텝. 첫 패턴은 3타 고정.
- **페이즈**: HP ≤ 최대의 1/2이면 전환 예약 → 현재 패턴·후딜 끝나고 미사일이 다 사라진 뒤 전환. 전환 중 무적 없음. 사망이 항상 우선.
- **0.35초 간격**: 본체는 패턴 시작 시 유효 판정 시각들을 `Boss1Missiles`에 미리 등록한다. 조준 미사일은 착탄 예정이 그 시각 ±0.35초와 겹치면 조준 시작을 미룬다. 이미 고정된 미사일이 있으면 본체가 다음 패턴 시작을 미룬다. 고정된 경고는 절대 바꾸지 않는다.
  - 조준 미사일의 비행 판정은 언제 맞을지 미리 알 수 없으므로 이 규칙은 **벽 착탄 시각**에만 적용한다.
- **조준 미사일**: 머리 옆에서 플레이어까지 선을 그려 1.6초 추적(점멸) → 0.4초 고정(색·두께 변경) → 그 방향으로 발사. 비행 중 몸체에 닿으면 피해(미사일당 1회), 벽에 닿으면 폭발(0.4H) 피해. 플레이어에 닿아도 터지지 않고 벽까지 날아간다.
- **난사**: 30발 각각 발사 순간의 플레이어 X ± 0.25H 안 무작위 지점에 착탄 원을 표시한다. 폭발 반경(0.4H)이 산포보다 커서 제자리에 있으면 반드시 맞는다 — 계속 움직여야 피할 수 있게 한 의도.
- **사망**: 모든 히트박스 끔, 미사일·충격파·경고 표시 즉시 소멸.

## 7. 검증

- 컴파일: Unity MCP 콘솔 확인
- 자동 테스트 1개(EditMode): 페이즈 경계(HP 정확히 1/2일 때 2페이즈)와 0.35초 간격 판정 함수
- 나머지(회피 가능 여부, 반격 창 체감, 리듬 High 유지)는 **플레이 테스트**로 확인 — 기획서 "플레이테스트 조정 항목" 체크리스트 사용

## 8. 결정 사항 (2026-11-12, 기획서보다 우선)

1. **3타 1타 높이**: 1.2H → **0.9H**.
2. **조준 미사일 판정**: 비행 중 몸체 판정 + 벽 착탄 폭발, 판정 2개. (공통 규칙 "비행 중 접촉 피해 없음"의 예외)
3. **조준 시간**: 추적 **1.6초** + 고정 **0.4초**.
4. **난사 산포**: 플레이어 위치 **±0.25H**. 제자리에 서 있으면 맞도록 해서 계속 움직이게 한다.
5. **2페이즈**: **예고(선딜레이)만 ×0.8, 패턴 사이 대기 0.4→0.25**. 부스트 스텝 정지·재사용 대기는 1페이즈와 같다.
6. **플레이어 피격**: 일단 `Debug.Log`만 남긴다. 체력·무적·사망·리듬 감소는 나중에.

### 가정 (구현하면서 다르면 알려주세요)

- "0.25"의 단위는 H로 본다 (0.25H ≈ 0.33 유닛).
- 조준 미사일은 플레이어에 닿아도 터지지 않고 계속 날아가 벽에서 폭발한다.

## 9. 후딜 및 난사 판정 조정 (2026-11-24)

모든 본체 패턴의 후딜을 기존 값에서 20% 늘렸다. 아래 값은 1·2페이즈에 동일하게 적용한다.
인스펙터에 저장된 후딜 값은 실행할 때 1.2배를 적용하므로, 기존 씬의 개별 설정도 같은 비율로 늘어난다.

| 구간 | 기존 기본값 | 적용 후 |
|---|---|---|
| 근접 1→2타, 2→3타 사이 | 각각 0.35초 | 각각 0.42초 |
| 근접 3타 종료 | 0.55초 | 0.66초 |
| 돌진 제동 | 0.60초 | 0.72초 |
| 도약 내려찍기 후딜 | 0.55초 | 0.66초 |
| 백스텝 후 연계 대기 | 0.30초 | 0.36초 |
| 후방 미사일 발사 후딜 | 0.50초 | 0.60초 |
| 미사일 난사 종료 후딜 | 0.60초 | 0.72초 |

선딜, 공격 판정 지속 시간, 패턴 사이 공통 대기, 재사용 주기, 패시브 조준 미사일 주기는 유지한다.
난사 미사일은 비행 중 플레이어와 접촉해도 터지지 않으며, 발사 시 표시한 도착 지점에서만 폭발 범위 피격 판정을 낸다.
난사에는 폭발 범위 밖의 보스 몸통 피격 판정을 추가하지 않는다.

## 10. 몸통 공격 판정 제거 (2026-11-24)

- 모든 패턴에서 보스 몸통을 별도로 검사해 플레이어에게 피해를 주는 판정을 제거한다.
- 근접 3타와 돌진의 공격 박스도 몸통 앞면 바깥에서 시작한다. 기존 전방 끝점과 높이, 피해량, 지속 시간은 유지한다.
- 도약은 수직 하강~착지 직후의 몸통 판정과 충격파를 사용한다. 미사일은 각 탄체·폭발의 기존 판정만 사용하며, 폭발 위치와 무관하게 보스 몸통에서 피해를 주는 처리는 없다.
- 몸통 포함 비율 설정과 Scene의 몸통 판정 편집·표시를 제거한다.
- 지형 충돌과 보스가 플레이어 공격을 받는 데 사용하는 본체 콜라이더는 유지한다.
