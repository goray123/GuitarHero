# 리듬 게이지 구현

Player 프리팹에 `PlayerRhythmGauge`와 `PlayerRhythmGaugeUI`를 연결했다. Main과 City01에서 같은 프리팹을 사용하므로 씬을 다시 배치할 필요 없이 적용된다. 게임 화면 좌측 하단 HUD에서 현재 게이지, 단계, 다음 평타의 공격속도와 공격력 배율을 확인한다.

## 적용 규칙

| 단계 | 게이지 | 공격속도 | 공격력 | 게임 시간 기준 감소량 |
| --- | --- | --- | --- | --- |
| Low | 0 이상 250 미만 | ×1.0 | ×1.0 | 12.5/초 |
| Normal | 250 이상 500 미만 | ×1.25 | ×1.0 | 25/초 |
| High | 500 이상 750 미만 | ×1.5 | ×1.25 | 50/초 |
| FEVER | 750 이상 1000 이하 | ×2.0 | ×1.5 | 100/초 |

- 기본 공격이 실제 피해를 주면 대상마다 +30을 획득한다. 같은 공격으로 같은 적의 여러 판정을 접촉해도 중복 지급하지 않는다.
- 음표는 실제 피해가 적용된 한 개마다 +15를 지급한다. 현재 음표 5개가 전부 맞으면 +75이며, 피해가 거절된 음표는 지급하지 않는다.
- 자연 감소는 FixedUpdate의 게임 시간으로 적용하므로 메뉴 일시정지와 히트스탑 중 멈춘다. 감소 도중 경계를 통과하면 남은 시간에는 다음 구간의 감소량을 적용한다.
- 공격 시작 시 배율을 저장한다. 준비·활성·후딜·접촉 지연과 3타 착지 후 구간까지 같은 배율을 사용한다. 도중에 단계가 바뀌어도 진행 중 공격의 피해량과 시간이 달라지지 않는다.
- 히트스탑과 낙하 물리, 스킬의 행동 제한 시간은 공격속도로 줄이지 않는다. 음표 스킬의 피해량은 별도 배율 규칙이 정해질 때까지 기존 값을 사용한다.
- 사망·재시작 또는 플레이어 비활성화 후 다시 활성화될 때 게이지를 0으로 초기화한다. 초기화 전에 발사된 음표가 나중에 적중해도 새 생명의 게이지를 올리지 않는다.

FEVER는 게이지 구간으로 동작한다. 별도 진입 충전, 최소 유지 시간, 획득 중단은 적용하지 않았다. 기획서의 Main 지속 가능성과 City01 경계 이탈 현상은 수치 조정을 위한 검토 항목이다.

## 다른 전투 시스템에서 연결하는 방법

기본 공격과 현재 음표 스킬은 이미 연결되어 있다. 퍼펙트 닷지·강화 평타와 플레이어 체력·보스 공격은 아직 프로젝트에 없으므로 해당 시스템을 만들 때 다음 API를 사용한다.

```csharp
// 강화 평타가 적에게 실제 피해를 적용한 뒤 대상마다 한 번 호출한다.
rhythm.RecordConfirmedDamage(RhythmHitKind.Enhanced, appliedDamage); // +60

// 체력 시스템이 보스 피해를 수락한 뒤 피격 이벤트마다 한 번 호출한다.
// 회피와 무적으로 피해가 거절되었다면 호출하지 않는다.
rhythm.NotifyBossDamageTaken(appliedDamage); // -100

// 플레이어 사망, 체크포인트 복구 또는 재시작 시 호출한다.
rhythm.ResetGauge();
```

0 이하·NaN·무한대인 피해에는 보상과 패널티가 적용되지 않는다. `ResetGauge`는 현재 공격을 취소하는 기능이 아니므로 사망 시스템에서 공격과 이동 중지도 함께 처리해야 한다.

## 조정 위치

Player 프리팹의 PlayerRhythmGauge에서 네 단계의 공격속도·공격력·자연 감소량과 기본 획득량, 강화 평타·음표 배율, 보스 피격 손실을 조정한다. 단계 경계는 250씩 고정되어 있다.

PlayerRhythmGaugeUI의 Screen Offset과 Panel Size로 확인용 HUD 위치와 크기를 조정한다. HUD의 모든 그래픽은 Raycast Target을 끄며 별도 입력용 EventSystem은 필요하지 않다.

## 검증 실행

```powershell
./Tools/ValidateRhythmGauge.ps1
./Tools/ValidateCombatFeel.ps1
```

설치된 Unity 6000.3.25f1로 Temp 아래의 별도 프로젝트를 실행한다. 원본 프로젝트의 씬이나 Play 상태를 변경하지 않는다. 실행이 끝날 때까지 대기하며 실패하면 명령이 오류를 반환한다.

- 리듬 결과: `Temp/RhythmGaugeValidation/rhythm-gauge-results.txt`
- 리듬 로그: `Temp/RhythmGaugeValidation/validation.log`
- 기존 전투 결과: `Temp/CombatFeelValidation/combat-feel-results.txt`

리듬 검증은 경계·증감·피격·중복 방지·투사체 초기화·HUD·정지·공격 배율 스냅샷과 공중 3타 착지까지 확인한다. 기존 전투 검증은 입력 예약, 슬라이드 캔슬, 타격감, 체력바와 중복 피해를 함께 확인한다.

### 기존 전투 검증의 기준 상태

현재 기존 전투 검증에는 체력바 관련 실패 4건이 있다. 숫자 위치를 1/100로 줄이는 기대값 2건과 잔상이 0.4초에 끝난다는 기대값 2건이 현재 HealthBarUI 구현과 다르다. 변경 전 HEAD의 공격 코드·프리팹으로 별도 실행해도 같은 4건이 실패하는 것을 확인했다. 리듬 게이지 작업에서는 이 체력바 동작과 기대값을 변경하지 않는다.

비교 결과는 `Temp/CombatFeelValidation/combat-feel-baseline-results.txt`와 `combat-feel-with-rhythm-results.txt`에 보관한다.
